# checklist.md — 质量检查清单

Pikesun 设计系统页面质量检查清单，按优先级分为 P0（必须全过）、P1（应该通过）、P2（加分项）。

在提交或发布任何页面之前，必须逐项核对本清单。

---

## P0 — 必须全过（8 项）

以下是不可妥协的底线标准。任何一项未通过，页面不得提交或发布。

### P0-1: 品牌色正确使用

- [ ] Primary #0071E3 出现在关键交互元素上（按钮、链接、焦点环）
- [ ] Accent #FF9500 用于强调和装饰（不超过页面 5% 面积）
- [ ] Pop #FF3B30 仅用于警告、错误、删除等危险操作
- [ ] Cream #fefcf6 作为页面主背景色
- [ ] Ink #1A1A2E 用于主文字
- [ ] Ink Light #4A4A5A 用于次要文字
- [ ] Ink Faint #8A8A9A 用于辅助文字
- [ ] 没有引入品牌色之外的颜色（除黑白灰和语义绿 #34C759）

### P0-2: 无禁止元素

- [ ] 没有 Bootstrap / Tailwind / Ant Design 等第三方 UI 框架的默认样式
- [ ] 没有 `text-shadow` 用于正文
- [ ] 没有 `border-radius: 50%` 之外的圆形组件（卡片、按钮使用 8-20px 圆角）
- [ ] 没有纯黑 `#000000` 或纯白 `#FFFFFF` 大面积背景（用 Ink 和 Cream 代替）
- [ ] 没有 `!important` 滥用
- [ ] 没有浮动元素 `float` 布局（使用 Flex/Grid）

### P0-3: 无 HTML 默认样式残留

- [ ] 链接没有默认蓝色 + 下划线（除非刻意保留在正文中）
- [ ] 列表没有默认 `list-style`（设计系统内使用自定义序号/项目符号）
- [ ] 按钮没有默认 `border`、`background`、`padding`（全部显式定义）
- [ ] 输入框没有浏览器默认 `outline`（使用自定义 `box-shadow` 焦点环）
- [ ] 标题没有默认 `margin`（全部显式定义）
- [ ] 图片没有底部空隙（`display: block` 或 `vertical-align: middle`）

### P0-4: 暖色基调背景

- [ ] 页面主背景为 Cream #fefcf6
- [ ] 卡片背景为纯白 #ffffff（与 Cream 形成层次）
- [ ] 整体色调温暖、不刺眼
- [ ] 暗色模式（如有）使用 Ink #1A1A2E 作为背景，不是纯黑

### P0-5: Serif + Sans 混排

- [ ] 标题使用 Fraunces（衬线）或 Noto Sans SC（无衬线）
- [ ] 正文段落使用 Noto Serif SC（衬线）—— App 场景可用 Noto Sans SC
- [ ] 辅助/UI 文字使用 Noto Sans SC
- [ ] 中英文混排时英文使用 Caveat 或 Fraunces 对应字重
- [ ] 字体加载有 fallback（`serif` / `sans-serif`）

### P0-6: 响应式可用

- [ ] 320px 宽度下所有内容可见、可读、可操作
- [ ] 768px 断点处布局正确切换（2 列变 1 列等）
- [ ] 1200px+ 内容不无限拉伸（max-width 约束）
- [ ] 图片不超出容器（`max-width: 100%`）
- [ ] 触摸目标不小于 44x44px（移动端按钮和链接）
- [ ] 没有水平滚动条

### P0-7: 每个 Section 使用不同布局

- [ ] 相邻 Section 不使用相同的布局模式
- [ ] 至少使用了 3 种不同的布局模式（参考 layouts.md）
- [ ] 暗色面板与浅色面板交替出现（Landing 场景）
- [ ] 页面整体有视觉节奏感

### P0-8: 不像是 AI 生成的模板

- [ ] 有独特的细节或视觉记忆点（一处即可）
- [ ] 不是"居中标题 + 三列卡片 + CTA"的模板套路
- [ ] 排版有手工调整的痕迹（如特殊字距、不对称布局、破格元素）
- [ ] 图片/插画风格统一，不与 Unsplash 通用素材雷同
- [ ] 中文字体选择有意义（不是系统默认中文字体堆砌）

## P1 — 应该通过（5 项）

应尽量通过的品质标准。少数项可根据场景豁免，但未通过则需要说明理由。

### P1-1: 至少一处视觉惊喜

- [ ] 有一个 Section 布局或效果是用户不会预期的
- [ ] 惊喜服务于内容传达，不是纯粹的炫技
- [ ] 示例：Bento Grid 破格图片、装饰性英文大字背景、倾斜排版、渐变遮罩

### P1-2: 使用 clamp() 实现流体尺寸

- [ ] 标题使用 `clamp()` 实现视口自适应
- [ ] 正文在移动和桌面之间有字号过渡
- [ ] Section 间距使用 `clamp()` 或百分比单位
- [ ] 不使用固定 px 值应对不同视口（至少关键元素使用流体值）

### P1-3: 交互元素有 Hover 状态

- [ ] 所有按钮有 hover 反馈（颜色变化 / 阴影 / 位移）
- [ ] 所有链接有 hover 状态
- [ ] 可点击卡片有 hover 效果
- [ ] Hover 状态有 `transition` 过渡（禁用 `transition: all`）
- [ ] 有 `active` / `:focus-visible` 状态（至少对按钮）

### P1-4: 移动端适配而非截断

- [ ] 移动端不是简单地将桌面端缩小
- [ ] 移动端重新组织了信息层级（不是隐藏部分内容）
- [ ] 导航在移动端有合适的呈现（汉堡菜单或简化导航）
- [ ] 移动端图片尺寸和比例适配小屏幕
- [ ] 移动端没有"横屏才能看全"的内容

### P1-5: 间距节奏正确

- [ ] 使用一致的间距单位（推荐 4px 或 8px 基准）
- [ ] 相邻元素间距符合亲密性原则（相关内容靠近，不相关内容远离）
- [ ] Section 之间的间距大于 Section 内部元素间距
- [ ] 标题与正文的间距大于正文行间距
- [ ] 页面边缘留白充足（>= 16px 移动端，>= 24px 桌面端）

---

## P2 — 加分项（4 项）

通过则显著提升品质，不通过不影响基本可用性。

### P2-1: 滚动揭示动画或微妙动效

- [ ] 使用了 Intersection Observer 或其他方式实现元素渐入效果
- [ ] 动画时长不超过 0.5 秒
- [ ] 动画曲线使用 `ease-out` 或自定义 cubic-bezier
- [ ] 动效不是"为动画而动画"，服务于信息呈现节奏
- [ ] 首屏元素不触发动画（初始状态就是可见的）

### P2-2: 装饰性数字或英文元素

- [ ] 页面中有装饰性的大数字（如 Section 编号 "01 / 02 / 03"）
- [ ] 或使用了英文装饰短语（Fraunces 或 Caveat 呈现）
- [ ] 装饰元素与页面内容有语义关联
- [ ] 装饰文字使用半透明或 outline 风格，不抢夺正文注意力

### P2-3: 尊重 prefers-reduced-motion

- [ ] 在 CSS 中使用 `@media (prefers-reduced-motion: reduce)` 禁用动画
- [ ] 或使用 JavaScript 检测用户偏好并关闭动效
- [ ] 减少动画后页面仍然正常可用

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

### P2-4: 图片突破容器边界

- [ ] 至少一张图片突破了其所在容器的边界
- [ ] 效果：图片一部分在卡片内，一部分延伸出去，制造层次感
- [ ] 使用了 `overflow: visible` + 负 margin 或绝对定位实现
- [ ] 在移动端仍保持可控（不超出视口）

```css
.image-breakout {
  margin-right: -40px;
  margin-bottom: -20px;
  position: relative;
  z-index: 1;
}

@media (max-width: 768px) {
  .image-breakout {
    margin-right: -16px;
    margin-bottom: -12px;
  }
}
```

## 检查流程

1. **开发完成后** — 开发者自检 P0，确认 8 项全部通过。
2. **设计评审前** — 设计师自检 P0 + P1，标记未通过项及理由。
3. **提交发布前** — 最终审查全表 P0 + P1 + P2，记录得分。

## 豁免规则

- P0 项不允许豁免。未通过则不得发布。
- P1 项最多豁免 1 项，需在提交说明中记录豁免理由。
- P2 项无豁免要求，通过越多越好。

## 得分

| 等级 | P0 | P1 | P2 |
|------|----|----|-----|
| 优秀 | 8/8 | 5/5 | 3+/4 |
| 良好 | 8/8 | 4/5 | 2+/4 |
| 合格 | 8/8 | 3/5 | — |
| 不合格 | < 8/8 | — | — |

---

*P0 全过 = 可以交付 | P1 全过 = 品质过关 | P2 = 锦上添花*
